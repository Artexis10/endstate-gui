## Why

We are migrating off LemonSqueezy as the license provider because it ties activation/validation to a third-party service whose availability, pricing, and policies we don't control. A self-hosted Ed25519-signed licensing system backed by our own API gives us full control over the license lifecycle, makes offline validation cryptographically sound rather than blind-cache trust, and aligns licensing with the new Paddle checkout flow.

## What Changes

- **BREAKING**: License activation, validation, and deactivation now target `https://substratesystems.io/api/license/*` instead of the LemonSqueezy checkout provider API.
- **BREAKING**: License key format changes from LemonSqueezy-issued opaque keys to Ed25519-signed base64 payloads generated by our Vercel API on Paddle purchase. Previously-issued LemonSqueezy keys will no longer activate.
- The Rust backend embeds an Ed25519 public key at build time and verifies the signature of every activation response before trusting it.
- Offline validation is now cryptographically gated: the cached activation response must carry a valid Ed25519 signature over `(license_key, fingerprint, activated_at, expires_at)` to be trusted offline.
- Periodic re-validation: when the cache is older than 30 days, the system attempts online re-validation before trusting it; on network failure within the 30-day window, the cached signature is still honored.
- The 3-device activation limit is enforced server-side by our API; the client surfaces the server's error message when the limit is reached.
- The "Buy Endstate" link in the activation screen points to the Paddle checkout URL instead of the LemonSqueezy checkout URL.
- Remove all LemonSqueezy-specific code paths, types, and test fixtures from `src-tauri/src/license.rs`.

## Impact

- **Code**
  - `src-tauri/src/license.rs` — replace LemonSqueezy HTTP client with substratesystems.io client; add Ed25519 verification (new dep: `ed25519-dalek`); extend cache schema with signature + expiry fields.
  - `src-tauri/Cargo.toml` — add `ed25519-dalek` and `base64` (if not already present).
  - `src-tauri/build.rs` or const module — embed the Ed25519 public key (PEM or raw bytes).
  - `src/components/app/LicenseGate.tsx` — update "Buy Endstate" URL to Paddle checkout; adjust any error messaging copy tied to LemonSqueezy.
  - `src/lib/license.ts` — no shape change expected, but verify bridge types still match.
- **Tests**
  - Rust unit tests: signature verification (valid/invalid/tampered), cache round-trip with new fields, 30-day re-validation logic, offline-within-window trust.
  - Frontend tests: updated checkout URL, error surfaces for `device_limit_reached`.
- **External dependencies**
  - Removes runtime dependency on LemonSqueezy API availability.
  - Adds runtime dependency on `substratesystems.io/api/license/*` (Vercel-hosted).
  - Build-time dependency on the Ed25519 public key being available to the build.
- **Migration / user impact**
  - Users holding LemonSqueezy keys must be re-issued Paddle-flow keys; a one-time re-activation is required after upgrade.
  - Cache files written by the prior version (without signature fields) will fail validation and force a re-activation.
